# smart-buyer

让 AI 先学会判断好坏，再替你挑。聪明买手可以用在购物、软件订阅、服务比较和技术方案选型：先研究“好的为什么好”和“容易踩的坑在哪里”，定好标准后再找候选，核实参数、实际成本和社区实践，最后说清楚哪个更值、为什么适合你。

## 可以帮你挑什么

- **日常购物**：耳机、键盘、家电都能从预算和使用习惯出发比较。“帮我挑一个 500 元以内的蓝牙耳机”；“A 和 B 两款机械键盘选哪个？”给父母买洗衣机，也可以把耐用和维修方便放在前面。
- **食品和耗材**：把规格、单价和实际品质一起算。“哪款响铃卷的蛋白质性价比高，同时别有旧油味？”便宜多少、少了多少、用起来差在哪，都值得查明白。
- **软件与服务**：功能表之外，看看套餐限制、续费成本和长期用户的反馈。“帮我比较这几款云盘，我主要备份照片，按一年实际要花的钱排一排。”
- **技术方案选型**：先了解各条路线解决什么问题、常见麻烦是什么，再结合自己的条件挑。“个人项目的数据库怎么选？帮我比较部署成本、维护难度和大家踩过的坑。”

- **选型前先做功课**：“我还没想好买哪款 NAS，先告诉我该看什么指标、哪些坑值得留意。”先研究好坏标准和失败模式，弄明白以后再开始挑。

## 为什么需要它

拿购物来说，普通的 AI 推荐很容易出现四类问题：先看到商品再倒推推荐理由；把列表页小包装起售价当成目标 SKU 价格；拿几篇带货文章自创指标；只看优点，遗漏酸败、缩水、易坏、难维护等失败模式。

`smart-buyer` 的设计思路是先建立评价体系，再接触候选：

1. 正向轨研究性能、体验和耐用性的增益指标；
2. 独立负向轨研究廉价劣质产品的常见缺陷、抽检/召回、维修数据和偷工减料路径；
3. 区分真实缺陷、品类天然局限、个人偏好和未证实风险；
4. 冻结核心参数、底线、风险指标和性价比公式；
5. 搜索候选并核实具体 SKU、总规格、实际价格和一手参数；
6. 去爱好者社区验证真实讨论，最后排序。

这个流程来自蓝牙耳机、油面筋、响铃卷等实际选购任务中的反复校正。响铃卷案例中，负向轨额外发现了油脂新鲜度、包装受潮、碎损和短时涮煮表现等只看蛋白质单价会漏掉的问题。

## 核心能力

- **正反双轨设标**：正向品质研究与负向失败模式研究相互隔离，减少围绕预设答案找证据。
- **反软文启发式**：只有单篇指南提出、又找不到原始依据的指标不能成为硬门槛；多篇文章转述同一来源只算一条证据。
- **风险分类**：不把品类天然限制或个人偏好误判成质量缺陷，也不凭理论风险给具体产品定罪。
- **成本放在同一把尺子上**：商品核实 SKU、总规格、运费和优惠条件；软件与服务核实版本、套餐和收费条件；技术方案把部署、维护、迁移投入也算进去，再按同一使用规模和周期比较。
- **数据溯源分级**：优先使用官方规格、实际包装标签和监管/标准数据；追不到原始出处的数字明确标为未核实。
- **实践验证自包含**：不依赖其他 Skill；实物商品从自身原生正向计数不少于 10 的社区内容里提取长期反馈和竞品对比。软件、服务和技术方案则结合版本文档、真实使用记录、问题跟踪和可复现测试，核对关键能力。
- **风险可见**：每个推荐都展示风险核对结果和到货验收建议，不让前期调研消失在最终报告里。
- **诚实降级**：负向证据或社区讨论不足时明确说明，不降低标准凑数。

## 输出内容

先说选哪个、适合谁，再把评价标准、候选差异、成本、实践证据和主要取舍摆出来。只想先弄清该看什么指标时，就先交付选型标准和常见问题；指定 A/B 时，围绕这两个比较。

购物报告会进一步列出：

- 核心参数、底线和主要失败模式；
- 推荐产品的具体 SKU 与价格口径；
- 参数核实状态和性价比计算过程；
- 风险核对与到货验收建议；
- 社区讨论来源、原生正向计数、具体观点和争议；
- 不推荐候选及具体原因；
- 当前价格的核验时间与数据局限。

## 方法边界

实物商品用社区口碑补充真实使用经验，参数、价格和规格查当期一手资料；软件、服务和技术方案结合版本、使用条件与实践证据判断。
